## 目标

帮助门店人员从手机拍摄的未知零件照片出发，找到可能匹配的产品规格。这个任务需要把视觉结果转化为使用者能够核对的产品候选，并具备用户管理、检索记录和后续运营的基础。

我承担项目技术负责工作，连接客户约束分析、算法验证、业务系统设计与成本评估。关键问题是：当产品目录中多数条目没有实物照片时，怎样利用已有规格数据完成识别与推荐？

## 输入

- 用户拍摄的零件图像，以及用于尺寸换算的参考物。
- 产品目录中的尺寸、螺距等结构化规格，以及可以构成检索文本的属性。
- 用于检测、分割、测量和匹配验证的标注与参考规格。
- 门店、用户角色和检索历史等业务信息。

拍摄角度、光照与反光情况不固定，客户也无法批量补拍产品图。方案因此不能直接依赖完整的产品图片库。

## 用户流程

以下按门店识别任务梳理基础使用路径：

1. 使用者提交零件照片，系统检测目标并分割零件与参考物。
2. 通过方向对齐、尺度换算和螺距估计，得到可与目录比较的测量结果。
3. 将结果与规格数据匹配，返回 Top-3 候选，供使用者核对。
4. 系统记录检索过程；管理人员在授权范围内查看历史与审计信息。

后续设计在查询中引入 VLM 提取视觉属性，再到规格文本向量库检索候选，最后结合尺寸测量精排。这一层属于架构设计与可行性研究，不混入已经完成的基础功能。

## 输出

我完成了检测、分割、PCA 姿态校正、参照物尺度换算、DFT 螺距估计与规格匹配等算法工作，并通过实验验证测量与推荐表现。

工程交付包括容器化 Demo、FastAPI 与 PostgreSQL 后端，以及角色权限、JWT、检索历史和审计能力。这些工作让视觉 Demo 具备可管理、可追溯的业务系统基础。

方案层面输出了分层 RAG 架构，并估算多家图像模型 API 的 Token 用量和成本，帮助客户比较预算与后续商业化路径。

## 任务边界

- **个人负责范围：**客户约束分析、技术路线、算法验证、业务系统设计与相关开发，以及客户成本评估。
- **阶段边界：**容器化 Demo 与后端开发不等于全场景生产上线；VLM 与向量检索部分按方案设计和可行性研究描述。
- **决策边界：**候选推荐辅助产品查找，仍需核对规格。样本上的实验表现不能作为任意拍摄条件下的准确率承诺。

## 验收标准

按现有材料整理的验证口径如下，具体客户签收条款和实验指标不在公开文章中展示：

- 在带参考规格的样本上核对尺寸、螺距误差和 Top-3 命中情况，说明样本与拍摄条件。
- 从图片提交到候选返回的链路能够复现，前端能使用结构化结果，历史与权限控制能被验证。
- 对比模型调用成本时，明确输入图像条件、Token 估算和适用假设。
- 后续 RAG 应与既有方案在同一评估集上比较召回、精排、延迟与成本；该项是继续验证的要求。

## 迭代

先围绕可测量的几何规格建立 CV 流水线，再补齐用户、权限和检索历史，让结果进入业务流程。随后，针对产品图片缺口，重新定义产品侧的数据表示，设计规格文本检索与视觉属性提取的组合。

这个项目让我更加重视“现有什么数据”与“结果怎样被核对”。下一步的价值应由实际推荐收益和成本解释，而不是由增加了多少模型来说明。
